1

What HomeFix is and how the pieces fit

HomeFix is a booking and field-service app for an appliance repair business. Customers book a repair and pay, technicians run their visits, and the owner and manager run the business. All of it lives in one phone app; each person sees only their own area after logging in.

Three projects (three Git repositories)

RepositoryWhat it isNeeded for the phone app?
businesshub-backendThe server (API): Node.js, Express, TypeScript, PostgreSQL via Prisma. Every rule and every amount is decided here.Yes — the app cannot work without it.
businesshub-reactnativeThe phone app: React Native with Expo, for customers, technicians and staff. This guide is about this one.Yes — it is the app.
businesshub-frontendThe website (Next.js). Same backend, same rules.No. Optional.

How they talk to each other

The one idea to remember The phone only shows things and sends what the user picked. The backend decides everything: who may do what, which times are free, every price and every allowed status change. That is why the backend must be running for the app to work.

Words you will see a lot

Terminal

The window where you type commands. On Windows: press Start, type PowerShell, open it. You often need two or three terminals open at once.

npm / npx

npm install downloads the project's libraries. npm run dev runs a script from package.json. npx tool runs a tool without installing it.

.env file

A small text file with settings and secrets (passwords, keys). Each project has a .env.example; you copy it to .env and fill it in. Never shared on GitHub.

Your PC's address on the Wi-Fi, like 192.168.1.5. The phone uses it to reach the PC. It can change, so check it each day.

Install its libraries

2

Find your PC's IP address

ipconfig

Look under Wireless LAN adapter Wi-Fi for IPv4 Address, for example 10.166.62.82.

3

Tell the app where the backend is

copy .env.example .env
notepad .env

Set the one line to your IP and port 4000, then save:

EXPO_PUBLIC_API_URL=http://10.166.62.82:4000
Why not "localhost"?On the phone, "localhost" means the phone itself. The phone must use the PC's Wi-Fi address. If you use the Android emulator instead, use http://10.0.2.2:4000.
4

Let the phone reach the PC

  • Phone and PC on the same Wi-Fi.
  • Windows Settings → Network → your Wi-Fi → set it to Private.
  • The first time Node.js asks "Allow access?", tick Private networks and allow.
CheckOn the phone's browser open http://<your IP>:4000/health. It must show {"status":"ok"…}. If it doesn't load, nothing else will work yet: see Troubleshooting.
Office or college Wi-Fi?Many of these block devices from talking to each other. Turn on your phone's hotspot, connect the PC to it, run ipconfig again and update .env with the new IP.

7

Create your Expo account

Expo makes the tools this app is built with. EAS (Expo Application Services) is their cloud: it turns the project into a real Android app (an APK) on their computers, so you don't need Android Studio.

1

Sign up

Go to expo.dev/signup, choose a username, email and password, then confirm the email Expo sends you.
2

Ignore the welcome page

After signing up, Expo shows "Get your project started" with npx create-expo-app. Don't run it — that makes a new empty app. You already have the project. Close the page.
3

Log in from the terminal

cd D:\Projects\businesshub-reactnative
npx eas-cli@latest login

It may open your browser: log in there and you'll see "Authentication successful". The terminal then says Logged in.

"Your username, email, or password was incorrect"This is your Expo password (not Gmail, not GitHub, not the app's login). If you signed up with Google or GitHub, set a password with "Forgot password?" on expo.dev, or use the browser login above.

What happens on expo.dev

  • The first build creates a project called businesshub-reactnative under your account and writes its ID into app.json (extra.eas.projectId). Commit that change.
  • Expo creates and keeps the app's signing key (keystore). Android only installs signed apps, and every update must be signed with the same key — so let Expo keep it.
  • Every build gets a page with live logs, a QR code and an Install button. Your builds list: expo.dev → your project → Builds.
  • The free plan builds in a shared queue (a few minutes' wait is normal) and includes a limited number of builds each month — see expo.dev/pricing.

Build the Android app (APK) in the cloud

You need a build only the first time, and again when a library with native code is added (for example the Razorpay, camera or photo libraries). Normal screen changes don't need a new build: the app gets them from your PC.

1

Bump the version (every new build)

In app.json, raise "version" (1.0.0 → 1.0.1) and "android" → "versionCode" (1 → 2). The app shows them on the login screen and in Settings → About, so you always know which build is on the phone.
2

Start the build

npx eas-cli@latest build --profile development --platform android

Test online payments with Razorpay

Customers can pay a completed visit online. The server creates the Razorpay order and decides the amount, Razorpay's own secure screen takes the card/UPI/bank details, and the server checks Razorpay's signature before marking the booking paid. In test mode no real money moves.

Before you start

  • Backend .env has RAZORPAY_KEY_ID=rzp_test_… and RAZORPAY_KEY_SECRET. Live keys (rzp_live_…) are refused on purpose.
  • You are using the HomeFix development build (not Expo Go, not the browser).
  • There is a booking that is Completed and not paid: the technician pressed "Complete visit" but not "Payment received".

Make a booking to pay (with the demo accounts)

  1. Customer (ravi@example.test) books a repair.
  2. Manager (manager@homefix.test) opens it → Assign technician → Rahul.
  3. Technician (rahul@homefix.test) opens the job → I'm on my way → I've arrived → Start work, fills "What did you find?" and "What did you do?" → Complete visit. Stop here.

Pay

  1. Log in as the Customer → Bookings → the completed booking.
  2. Under Payment: a yellow Test mode note and Pay ₹… online. Tap it.
  3. In Razorpay: UPI → success@razorpay, or Netbanking → any bank → Success on the test bank page.
  4. Back in the app: "Payment successful", the booking shows Paid ₹… by online and View receipt.
Try a failed payment tooUse failure@razorpay (or Failure on the bank page). You see an error, the booking stays unpaid, and you can pay again.
CheckThe receipt has a receipt number (RC-…), the online payment reference (pay_…) and the right total. Staff see the same payment on the website and in the app.
NeverPut live Razorpay keys, real card numbers or the .env file in Git, chats or screenshots.

How one screen works, end to end

Example: the customer taps Confirm booking.

LayerIts only job
Screen (src/features)Show things, collect what the user picks, show loading and errors.
Query hook (src/lib/queries)Name the action ("create a booking"), cache results, refresh lists afterwards.
src/lib/api.tsSend the request with the login token; turn errors into readable messages; a "401" logs you out.

Important things to know

The backend decides

Free times, prices, totals and who may do what are decided by the server. The app never works these out itself. Hiding a button is only for looks; the server checks again.

India time, always

All dates and times are shown in India time (IST), whatever the phone's setting. The server stores times in UTC.

Logging in on the phone

The app logs in with the header X-Client: mobile, gets a token, keeps it in the phone's secure keystore and sends it as Authorization: Bearer ….

Expo Go vs your own build

Expo Go can't contain Razorpay's native code, so Pay online is hidden there. Your development build has it.

When you need a new APK

Only after adding or upgrading a library with native code, or changing app.json plugins/permissions. Screen and logic changes reach the phone from npx expo start.

Always bump the version

Before each build, raise version and versionCode in app.json. The login screen shows them, so you know which build you're testing.

The Expo crash fix

scripts/patch-expo-ui.js runs after every npm install. It stops a crash in Expo SDK 57 (UnsatisfiedLinkError … clearAllContentOrigins) when the development build opens the app. Remove it once Expo fixes the bug.

Secrets

.env files are ignored by Git. Never commit keys or passwords. Razorpay runs in test mode only.

Your IP changes

New day, new Wi-Fi or a hotspot: run ipconfig and update EXPO_PUBLIC_API_URL, then restart npx expo start.

App colours

8 palettes (Navy default) and light/dark live in src/ui/theme.ts. Screens use useAppTheme(); no colour is hard-coded in a screen.

Troubleshooting

You seeWhyFix
"Can't reach the server…" in the appBackend not running, wrong IP, different Wi-Fi, or firewall.Check http://<IP>:4000/health on the phone's browser. Run npm run dev, update .env IP, set Wi-Fi to Private, allow Node.js, or use the phone hotspot.
